BMW · early 1990s · Bosch Motronic

This is a car’s brain.
We got it to boot on a laptop.

Not a simulation of “how engines work.” The actual program from a ~1990 BMW engine computer — opened, explained, rebuilt, and finally run in an emulator until it checked itself and said it was alive.

The box under the hood

In a BMW E30 318is (M42 engine, about 1990–91) sits a Bosch Motronic M1.7. Part number 0261200175. Software 1267356378. Inside: a Siemens SAB80C515 chip and 40,960 bytes of firmware — a frozen program that decides when to squirt fuel and when to fire the spark plugs.

An ECU doesn’t “drive.” It listens to sensors, then commands injectors and coils thousands of times a minute so the engine keeps running.

It listens

  • Crankshaft position / speed
  • Throttle
  • Airflow
  • Temperatures
  • Battery voltage
ECU 40 KB firmware

It commands

  • Fuel injectors
  • Ignition coils
  • Idle valve
  • Warning / fault memory
  • Shop diagnostics line

First we had to understand it

The binary is opaque until you reverse-engineer it: follow the code, read the chip datasheets, and write down what each job does. We ended up with a human-readable map of eleven jobs — reset and timing, crank sync, sensors, load, fuel, spark, idle, limiters, faults, diagnostics, integrity checks — plus hundreds of named functions and calibration tables.

That map is the product. Everything after it is a way to prove the map.

Proof A — rebuild from the map

From the written description alone, we wrote a fresh model in TypeScript. No original binary inside. Twist a virtual throttle, spin a virtual crank, and you can watch mode, fuel pulse width, and spark advance respond — in the browser, with every number tagged “proven from the binary” or “assumed because the writeup didn’t settle it.”

96 automated tests. One self-contained bench page.

Proof B — run the real program

Separately, we taught the MAME emulator this specific chip and board: missing peripherals, fake sensor voltages, fake crank pulses. Then we loaded the original 40 KB ROM — the same bits that lived in the car — and let it execute.

In 800 ms of emulated time it ran 494,680 instructions, finished its ROM checksum path, and entered its supervisor. A separate chip self-test suite: 55 checks, all pass.

The moment that matters

The old brain woke up.
Not as a screenshot of code — as a program running.

Crank edges arrived. The capture routine ran. The main loop ran. We’re not claiming a finished virtual car yet — tooth geometry and some equations are still assumed — but the firmware boots, checks itself, and accepts the outside world we feed it.

One sentence: we reverse-engineered a 1990s BMW engine computer into a map, rebuilt the map as a live demo, and also ran the original firmware for nearly half a million instructions until its own integrity check passed.
